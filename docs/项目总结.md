## 1. 项目背景与用户画像

### 1.1 用户在为谁做

不是"做一个识字 App"，而是"让妈妈能自己读出药品说明书、看懂孙子发来的消息"。

**用户画像（决定了所有设计取舍）**：

- 约 50 岁，河南农村生活背景，务农/家务为主
- 未完整接受义务教育，**识字量很低但能说标准普通话**
- **有拼音基础**：会拼读，这是本项目最大的教学抓手
- 信仰佛教，自尊心强 —— **UI 语气必须稳重、像"上课"，绝不能儿童化**
- 日常有学习意愿，能坚持，但单次注意力有限

### 1.2 由此推导出的设计约束

| 画像特征 | 设计决策 |
|---|---|
| 成人、自尊心强 | 大字体、正楷体；**不用卡通形象、不用"小朋友""太棒了"这类口吻**；配色沉稳 |
| 有拼音基础 | 拼音是**一等公民**（独立 tab），汉字全部带注音（ruby 排版） |
| 河南农村生活 | 歇后语选"一听就熟"的平民生活款；故事屋含 80 年代农村/家庭向原创故事 |
| 信仰佛教 | 内容选材**回避宗教、政治、迷信、神仙**（见 `lib/data/xiehouyu.dart` 头部注释） |
| 注意力有限 | 复习每天限量；单页只做一件事；按钮大、层级浅 |
| 平板使用 | 横屏适配（`lib/widgets/landscape_scope.dart`）；手写板要够大写 |

**已确立的 UI 原则**：移除面向中老年用户的重复/冗余选项，避免"假选择"（给了选项但两个都一样的体验）。

## 6. 语音系统（本项目技术核心）

### 6.1 为什么不直接用系统 TTS

1. 系统 TTS 装上什么引擎不确定，母亲平板上可能是个难听的引擎
2. TTS 对拼音字母、多音字处理不可控
3. 长文本在部分 ROM 上会闪退

**方案**：开发机上用 edge-tts（微软神经网络音色）把**每一句会念的话**预生成为 mp3，打包进 APK。

### 6.2 流水线

```
tool/voice_list.json          # 清单：要合成哪些文本 → 输出什么文件名
        ↓  tool/gen_audio.py  # 调 edge-tts 合成
assets/audio/*.mp3            # 慢速档（rate=-30%）
assets/audio_norm/*.mp3       # 原速档（rate=+0%）
        ↓  tool/rebuild_manifest.dart
lib/data/voice_manifest*.dart # key=要念的文本, value=asset 路径（自动生成，勿手改）
        ↓  运行时
VoicePlayer.speak(text) → 查 map → MethodChannel → 原生 MediaPlayer 播放
```

**配置**：voice = `zh-CN-XiaoxiaoNeural`，pitch = `+0Hz`，rate 双档（应用内设置可切换，**与系统语速分离**）。

### 6.3 运行时播放链路

```
Dart:  VoicePlayer.speak(text)
         │ 查 kVoiceManifest / kVoiceManifestNorm
         ├─ 命中 → MethodChannel('wanqing/audio').playAsset(path, speed)
         │           └─ Kotlin: MediaPlayer().setDataSource(asset fd)
         └─ 未命中 → TtsService.speakRaw(text)  【回落系统 TTS】
进度回报：EventChannel('wanqing/audio/progress')
```

**Kotlin 侧三条硬约束**（`MainActivity.kt` 头部注释，都是踩过的坑）：

1. **MediaPlayer 全部方法只在主线程调用** —— 跨线程触碰会 native 崩溃（荣耀 ROM 上实测）
2. **不能用 `prepare()` 阻塞主线程** → 改用 `prepareAsync()`，否则 ANR、屏幕静止
3. **进度轮询 200ms 一次**，也必须在主线程

### 6.4 三条加固（v1.15 起）

| 机制 | 解决的问题 |
|---|---|
| **看门狗** | 开播后超过"时长 + 2.5s"没收到完成回调 → 自动终止复位。旧版会永久卡在播放态 |
| **失败不盲目回落 TTS** | 预生成音频 native 报错 → 静默复位，**不**再丢给系统 TTS 撞崩溃路径 |
| **stop 递增代际号** | 用户点终止后，迟到的完成回调/回落结果一律作废 |

### 6.5 TTS 铁律

> **只有真汉字能进语音通道。拼音字母绝不经过 `VoicePlayer`。**

原因：把 `"b"` 送给 TTS，它会念成英文字母 "bi:"。所以声母教学念的是**呼读音汉字**（b→玻、p→坡…），这也是人教版拼音教学本身的做法。

## 7. 拼音呼读音机制（理解 v1.17 的前提）

### 7.1 为什么用呼读音

系统 TTS 和任何云端 TTS **都念不了拼音字母**。人教版拼音教学本身就用汉字呼读音教声母/韵母，所以本模块朗读呼读音汉字，听感与学校一致。

### 7.2 `readText` 字段

`pinyin_course.dart` 里三类（Shengmu/Yunmu/Zhengti）都有一个可选字段：

```dart
final String? readText;   // 朗读时送 VoicePlayer 的文本；null 表示沿用 huduyin
```

用途：当呼读音汉字的**字面声调**与**教学要念的声调**不一致时，指向一条专属音频。

### 7.3 B 类隔离（重要设计）

问题：如果直接改"得"字的音频为 dē（一声），那么在词组"得到"里也会被念成 dē —— 错了。

解法：建**隔离条目**，用带中间点的 key：

```dart
Shengmu('d', '得', readText: '得·py'),   // → assets/audio/py_de.mp3（念 dē）
Shengmu('r', '日', readText: '日·py'),   // → assets/audio/py_ri.mp3（念 rī）
```

这样"拼音教学读 dē"，而"得到"仍读 dé 到，互不污染。

> ⚠️ **坑**：key 含中间点 `·`，用正则提取时 `[^'\\]` 这类字符类会漏掉它。验证脚本必须用 `re.escape(key)`。

## 8. 复习与进度算法

`lib/services/review_service.dart`：

```dart
static const List<int> intervals = <int>[1, 3, 7, 30];  // 对应 stage 0..3
```

- **到期判定**：`stage < 4` 且 `距上次复习天数 >= intervals[stage]`
- **队列排序**：越生疏越前（stage 升序）→ 越久没复习越前（lastReviewDay 升序）
- **记录结果**：答对升档（stage+1），答错回档
- **stage 4 = 毕业**（不再进到期队列），但"复习专区"可手动复盘全部已学字

> 📌 **注意**：早期文档/口述里出现过"10分钟/1天/3天/7天/15天"的说法，**以源码 `[1, 3, 7, 30]` 为准**。

## 10. v1.17 专题：拼音声调修正（完整来龙去脉）

这一节记录一次**真实翻车与纠偏**，接手者务必读完，否则极易重蹈覆辙。

### 10.1 起因

用户反馈：声母 `d` 念成了 "dei"，`t` 念成了四声的 "tè"。

### 10.2 第一次判断（对了一半）

正确部分：拼音教学用**呼读音**，呼读音汉字的字面声调 ≠ 教学实际发音。人教版教声母 `t` 时念 **tē（一声）**，不是"特"的本音 tè（四声）。

**错误推广**：我据此断言"拼音教学**一律**念一声"，并把韵母 `e`（鹅）、`ao`（奥）、`ang`（昂）也改成用一声汉字（婀 ē、熬 āo、肮 āng）合成。

### 10.3 用户推翻（关键纠错）

> "这个 e 听着是四声……教材标准的四声到底从哪里来的信息，我从来都没听说过四声是标准，这样的话岂不是老师全教错了。"

用户是对的。**正确规则**：

| 类别 | 规则 | 示例 |
|---|---|---|
| **声母** | 一律念**一声**呼读音 | 特 tē、得 dē、讷 nē、勒 lē、日 rī |
| **韵母** | 按**自然声调**读 | 鹅 é（二声）、爱 ài（四声）、奥 ào（四声）、昂 áng（二声）、儿 ér（二声） |
| **整体认读** | 按**自然声调**读 | 日 rì（四声） |

韵母本身就有自己的声调，教材里"ā á ǎ à"四声都教，不存在"统一念一声"。

### 10.4 客观验证方法（这套方法值得复用）

主观"听着像几声"会吵不出结果，改用**基频（F0）斜率**客观判定：

`tool/pitch_check.py`（praet-parselmouth）：

```python
snd = parselmouth.Sound(path)
pitch = snd.to_pitch(time_step=0.01, pitch_floor=75, pitch_ceiling=500)
slope = np.polyfit(voiced_times, voiced_f0, 1)[0]
# |slope| < 8 Hz/s → 一声(平)   > 8 → 二声(升)   < -8 → 四声(降)
```

**关键坑**：清辅音（t-/d-/n-/l-/r-）开头的气声没有浊音，会拉低前 20% 的基频，产生**假的"升调"读数**。必须只分析元音核心（后 60%）。

**验证结果（9 项，8 项符合预期）**：

| 项 | 预期 | 实测 | 结论 |
|---|---|---|---|
| 韵母 e 鹅 | 二声 | 升 | ✅ |
| 韵母 ao 奥 | 四声 | 降 | ✅ |
| 韵母 ang 昂 | 二声 | 升 | ✅ |
| 韵母 ai 爱 | 四声 | 降 | ✅ |
| 韵母 er 儿 | 二声 | 升 | ✅ |
| 整体认读 ri 日 | 四声 | 降 | ✅ |
| 声母 d 得（教学） | 一声 | 平 | ✅ |
| 声母 t 特（教学） | 一声 | 平 | ✅ |
| 声母 r 日（教学） | 一声 | 轻微上扬+尾降 | ⚠️ 浊辅音 r 起振所致，可接受 |

**附带发现**：edge-tts 把孤立音节强制念成一声是**不稳定**的 —— 实测"婀(ē)"被合成成降调（-142 Hz/s）、"肮(āng)"也是（-177 Hz/s）。**用户的耳朵没错，是一声字本身被念错了。** 这直接证明了改用自然调汉字是对的。

### 10.5 最终改动清单

| 文件 | 改动 |
|---|---|
| `lib/data/pinyin_course.dart` | 韵母/整体认读**去掉** `readText`（回归自然调）；保留声母 `d`/`r` 的 `readText: '得·py'/'日·py'`；修正注释 |
| `tool/voice_list.json` | 删除 `ym_2253`(鹅)/`ym_2258`(奥)/`ym_2268`(昂) 的 `tts_text` 覆盖；删除孤立条目 `py_ai`/`py_er` |

### 10.6 另一个教训：源码对了但没重新打包

用户测出问题后非常挫败（"花的时间太久了……进展却一直在原地打转"）。**根因**：源码已修对，但 `dist/` 里一直是 v1.16 的旧包，**从没重新打包**。

> 📌 **流程教训**：改完数据/音频后，必须**重新 build APK** 再验证。测旧包等于没改。
> 建议在修完后先跑 `tool/` 下的试听脚本导出样本给用户听，确认后再打包。

## 14. 支持者排错手册

**Q：改了音频但 App 里还是老声音？**
A：99% 是没重新打包。执行 §9.2 重新 build，装新 APK。

**Q：某句话念得怪/没声音？**
A：先用 `tool/pitch_check.py` 检查基频；再查 `voice_manifest.dart` 里该文本是否命中（注意 key 里的 `·` 要 `re.escape`）。

**Q：构建报 Gradle 下载失败？**
A：`GRADLE_USER_HOME` 没设对。必须是 `D:/gradle_user_home`。

**Q：构建报 JAVA_HOME 无效？**
A：用了 `/d/jdk/...` 这类 POSIX 路径。改成 `D:/jdk/...`。

**Q：想加新的朗读内容？**
A：① 在 `tool/voice_list.json` 加条目 → ② 跑 `gen_audio.py` → ③ 跑 `rebuild_manifest.dart` → ④ 重新打包。

**Q：从 GitHub clone 后能直接构建吗？**
A：不能。缺三样：**签名密钥**（自建，§9.1）、**`android/local.properties`**（填本机 SDK 路径）、**Gradle 缓存**。前两样都在 `.gitignore` 里，按 §9 补上即可。
