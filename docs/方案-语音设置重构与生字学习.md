# 第一部分 · 语音设置重构

## 1.1 现状问题（含代码位置）

### 现象
设置页「朗读嗓音」一行出现 **4 个选项**：`自动（系统推荐）` + 3 个排在一起的 `zh` 选项；4 者实际播放出来是**同一种声音**。

### 根因（一层代码缺陷 + 一层引擎行为）

| # | 层 | 代码位置 | 问题 |
|---|---|---|---|
| 1 | 列表生成 | `lib/screens/settings_screen.dart:432` | 硬编码插入第 1 个 chip「自动（系统推荐）」，**与下面实际嗓音无关**，永远多出一项 |
| 2 | 列表生成 | `lib/screens/settings_screen.dart:434-441` | 把 `getZhVoices()` 返回的每一条**原样**生成一个 chip，**没有任何去重、没有任何名称翻译** |
| 3 | 数据采集 | `lib/services/tts_service.dart:76-93`<br>（尤其第 82-88 行） | `getZhVoices()` 只做 `locale.startsWith('zh')` 过滤后**直接 add**，**零去重**；且只保留 `name` + `locale`，丢弃了一切可用于区分的信息 |
| 4 | **应用（决定性）** | `lib/services/tts_service.dart:100-128`<br>（尤其第 107 行） | `applyVoice()` 按 **`name` 精确匹配后取第一个命中项** → 只要多条上报的 `name` 相同（或用户选中的 name 恰好等于被折叠掉的那条），**无论点哪个 chip，最终 `setVoice` 落到的都是同一个物理嗓音** |
| 5 | 初始化 | `lib/services/tts_service.dart:52-62` | `init()` 遍历嗓音时是「**每命中一个 zh 就 `setVoice` 一次**，遇到含「普通话/Chinese/中文」才 `break`」→ 启动过程中 TTS 被反复切换多次。这既拖慢冷启动，又进一步强化「选什么都一样」的观感 |
| 6 | 引擎行为 | 设备侧（Honor MagicPad2） | Android 系统 TTS 对中文**普遍以多个 locale/name 变体上报同一个物理嗓音**（`zh-CN` / `zh_CN` / `cmn-Hans-CN` / `zh-Hans-CN`）；部分引擎在拿不到可读名称时会把 `name` **直接回写为 locale 字符串**（即 `name == "zh-CN"`），于是 chip 上就是三个「连在一起的 zh 选项」 |

> ⚠️ 第 6 条属于**引擎侧推断**（当前 adb 无设备在线，无法真机 dump 复核）。第 1–5 条是**代码层确定缺陷**，无论引擎是否上报变体都应修。
> **建议 Engineer 加 1 行诊断**：在 `tts_service.dart:78` 后 `debugPrint(voices.toString())`，`flutter logcat` 抓一次真实列表，即可确认第 6 条并校准第 2 节的标签映射表。

### 根因一句话
**`getZhVoices()` 只按 locale 前缀过滤、不做去重（`tts_service.dart:76-93`），`applyVoice()` 又只按 name 匹配取首个（`tts_service.dart:100-128`），而 Android TTS 把同一中文嗓音以多个 locale/name 变体重复上报 —— 于是列表里 3 项 +「自动」1 项看着 4 个选项、实际全指向同一个嗓音。**

### 顺带发现的 2 个小 bug（不在本次需求内，但建议一并修）

| 位置 | 问题 | 建议 |
|---|---|---|
| `lib/screens/settings_screen.dart:33-34`<br>vs `lib/state/app_state.dart:25` | 语速**默认值不一致**：`AppSettings.speechRate` 默认 `0.2`（很慢），但 UI 找不到匹配档位时回落 `rateIdx = 1`（= `0.3` 慢速）。极端情况下界面显示「慢速」而实际播「很慢」 | 统一改为 `rateIdx = 0`（对齐默认 0.2） |
| `lib/services/tts_service.dart:184-187` | `speakChar` 里 `if (w == char) { await _speak(char); ... }` 的 `return;` 缩进错位，虽不影响运行但可读性差 | 顺手对齐缩进 |

## 1.2 方案：重构后的语音选项

### 1.2.1 四步流水线（替换 `getZhVoices()` 的实现）

| 步骤 | 规则 | 目的 |
|---|---|---|
| **① 宽进过滤** | 取 `locale` 首个 subtag（`_` 统一替换为 `-`，转小写），命中 `zh` **或** `cmn`（普通话的 ISO 639-3 码）即入选 | 不漏掉 `cmn-Hans-CN` 这类写法 |
| **② 归一化 key** | `key = normName + '|' + normLocale`<br>· `normName` = `name.trim().toLowerCase()`，去全/半角空格；**若 `normName` 等于归一化后的 locale 本身（如 `zh-cn`），则该 name 视为「无信息量」，统一记为 `#generic`**<br>· `normLocale` = 语言 + 地区，仅保留 `zh-CN` / `zh-TW` / `zh-HK` / `zh-SG` 四档（`cmn-hans-cn` → `zh-CN`；地区缺失时按 name 里是否含「台灣/台湾/TW」补，否则默认 `zh-CN`） | 把「同一嗓音的不同写法」折叠成同一个 key |
| **③ 同 key 择优** | 同一 key 内按序比较，取分最高的一条：<br>**(a)** `zh-CN` 优先于 `zh-TW/HK/SG`（母亲是河南人，大陆普通话最贴近）<br>**(b)** name 含「普通话」> 含「中文」> 含 `Chinese` > 其它<br>**(c)** 同分取引擎上报顺序中靠前的（引擎通常按推荐度排序） | 折叠后保留最合适的一条，而不是随机第一条 |
| **④ 排序输出** | 大陆普通话 → 其它 zh 变体 → `#generic` | 把最该用的放第一个 |

### 1.2.2 标签映射（把引擎的机器名翻译成母亲看得懂的中文）

| 原始 name / locale 特征 | 显示标签 |
|---|---|
| name 含「普通话」且 `normLocale == zh-CN` | `普通话` |
| name 含「中文」或 `Chinese`（大小写不敏感） | `中文` |
| `normLocale == zh-TW` 或 name 含「台灣/台湾」 | `中文（台湾腔）` |
| `normLocale == zh-HK` 或 name 含「粵/粤/廣東话」 | `中文（粤语）` |
| `name == locale`（引擎没给真名，记 `generic`） | `系统嗓音` |
| 以上都不匹配（第三方引擎自定义名） | **原样显示 name**（不臆造翻译），长度 > 12 字符时截断 + 省略号 |

> 若同一标签在去重后仍出现两次（如两个不同引擎都叫「中文」），**追加序号**：`中文` / `中文 2`。宁可朴素，也不要两个长得一模一样的选项（这正是用户这次吐槽的核心观感）。

### 1.2.3 去重后有几项，UI 怎么呈现

| 去重后数量 | UI 呈现 | 理由 |
|---|---|---|
| **0 个** | **隐藏整行**，改显示一行只读说明：`朗读声音由平板提供，可在「系统设置 → 文字转语音」里开启中文语音。` | 现状文案（`settings_screen.dart:427`）是开发者黑话（"首选引擎""语音数据"），母亲看不懂。**但要保留**，因为这是"没有声音"时的唯一自救指引 |
| **1 个** | ✅ **推荐：隐藏整行**，App 静默应用这唯一嗓音 | **只有一个选项的选择器是「假选择」**：母亲点来点去没变化 → 会以为"我点坏了"。她本就畏难自卑，这个挫败点必须消灭 |
| **≥ 2 个** | 显示：`自动（推荐）` + 去重后的 N 个嗓音 chip（沿用现有 `_VoiceChip`，点一下试听） | 此时选择才有意义 |

> **备选（供拍板）**：1 个时显示只读一行「朗读嗓音：普通话（本机自带）」，不可点。
> 我的判断是**隐藏更干净** —— 设置页的核心价值是"能改的东西"，不能改的信息放在设置页里只会稀释注意力。

### 1.2.4 是否保留「自动（系统推荐）」

**✅ 保留，但它是「兜底状态」而非「并列选项」，且默认选中。**

三条理由：
1. **它是唯一的安全回落值。** 用户手动选了某个嗓音后，若日后系统 TTS 升级、换引擎、或语音包被清理，存下的 `name` 会匹配失败。`applyVoice()` 已有兜底逻辑（`tts_service.dart:113-123`：`chosen == null` → 自动挑最优）。若列表里没有「自动」这个可达状态，用户会**永久卡在一个失效选项上且无从恢复**。
2. **它是首次启动的默认值。** 母亲不会主动去挑嗓音，`null`（自动）必须是一个合法且最优的默认态。
3. **它让"去重后只剩 1 个"时的隐藏决策成立** —— 因为「自动」≡ 那唯一一个嗓音，隐藏整行不损失任何能力。

**改名建议**：`自动（系统推荐）` → **`自动（推荐）`**。母亲不关心"系统"是什么，且"系统推荐"四个字对她更像警告语。

### 1.2.5 必须一并改掉的初始化缺陷

`lib/services/tts_service.dart:52-62` 的「边遍历边 setVoice」改为：**先遍历选出唯一最优的一条，最后只 `setVoice` 一次**。收益：冷启动少 N 次引擎切换调用；消除"选了 A 实际播 B"的残留可能。

## 1.3 方案：语速 / 音调调节项

### 1.3.1 当前设置面板完整清单（逐项核对自 `settings_screen.dart`）

| # | 区块 | 项目 | 档位 / 形态 | 代码位置 | 是否属于"与系统重复的同类项" |
|---|---|---|---|---|---|
| 1 | 显示设置 | **字号** | 4 档：小 1.0 / 中 1.15 / **大 1.3（默认）** / 超大 1.5 | `:49-57` | ❌ **不算重复**（见下方说明） |
| 2 | 显示设置 | **语速** | 3 档：很慢 0.2（默认）/ 慢速 0.3 / 稍快 0.4 | `:60-68` | ⚠️ **表面重复，实质不同**（见 1.3.3） |
| 3 | 显示设置 | **按钮大小** | 3 档：标准 1.0 / 大 1.12 / 特大 1.25 | `:71-79` | ❌ App 独有，系统无此概念 |
| 4 | 显示设置 | **显示拼音** | 开关（默认开） | `:82-87` | ❌ App 独有 |
| 5 | 显示设置 | **朗读嗓音** | chip 列表 + 点选试听 | `:91` | ⚠️ **需重构**（本方案 1.2） |
| 6 | 进度备份与恢复 | 备份进度 / 恢复进度 | 2 个大按钮 | `:97-114` | ❌ App 独有 |
| — | — | **音调** | **不存在** | — | ❌ **App 内本来就没有，无需改动** |

**关于"字号是否也算重复"**：系统确实也有「显示大小 / 字体大小」。但**不算重复**，理由：Android 的字体缩放是**全局且粗暴**的，会把 App 内的布局撑破（溢出、裁切）；而 App 内字号只作用于 `AppDimens`（`app_dimens.dart:79` `fs()`），是**受控的、不会崩版**的。两者是"粗调 vs 精调"关系，不是重复。**建议保留。**

### 1.3.2 处置结论

| 项目 | 结论 |
|---|---|
| 字号（4 档） | ✅ **保留** |
| 按钮大小（3 档） | ✅ **保留** |
| 显示拼音（开关） | ✅ **保留** |
| **语速（3 档）** | ✅ **保留**（论证见 1.3.3）+ 增强：切换后立即试听一句 |
| 朗读嗓音 | 🔧 **重构**（去重 + 翻译 + 单嗓音时隐藏） |
| 音调 | ❌ **不加**（App 内本来就没有；系统可调，且对"听清"的帮助远小于语速） |
| 备份 / 恢复 | ✅ **保留** |

### 1.3.3 【重点】App 内语速档位：保留还是移除？—— 结论：**强烈建议保留**

**五条专业论证：**

1. **作用域根本不同（最关键）。**
   系统 TTS 的语速是**全局**的：一旦调慢，微信语音播报、地图导航、无障碍朗读、短信播报**全部跟着变慢**。母亲若为了识字去系统里调，她大概率**不记得自己改过、更不会改回来**，等于给她（和家里其他用这台平板的人）埋了一个隐蔽的全局副作用。App 内语速只作用于本 App，随时可改回，零副作用。

2. **默认值不可控，这是核心体验的生死线。**
   系统 TTS 出厂语速是「正常」（`1.0`）。对"会念但不识字"的零基础老人，**1.0 语速几乎等于听不清**。若移除 App 内档位，就必须要求用户（或子女）**先去系统里调一次**——这是一道必须跨越的门槛。跨不过去，"听清读音"这个核心体验**直接不成立**。而 App 内默认 `0.2`（很慢）是**开箱即用**的。

3. **可发现性差异巨大。**
   母亲不会去翻系统设置（她甚至不知道那是什么）。App 内是一档一档点、看得见摸得着。
   > 📌 **顺带增强**：当前语速档位**切换后没有试听**（对比 `_VoiceRow._pick` 会试听，`settings_screen.dart:404`）。建议**切换语速后立即 `speak` 一句样板句**，让母亲"听到差别"——否则她不知道自己刚才改了什么。

4. **与嗓音/引擎解耦，跨场景稳定。**
   系统 TTS 设置页里语速是**和引擎绑定**的，换引擎可能重置语速。App 内每次 `init()` 都会重新写入 `setSpeechRate`（`tts_service.dart:44`），**换嗓音、换引擎、重启 App 都稳定**。

5. **成本极低。**
   3 个 chip + 1 行 `setSpeechRate`，零依赖、零维护成本。移除它省不下任何复杂度，却要付出引导成本（见下）。

**如果用户坚持移除，后果是什么（必须说清）：**

| 后果 | 说明 |
|---|---|
| ① **首次体验直接崩塌** | 母亲第一次打开 App 听到的是系统默认语速 1.0 → 听不清 → "我学不会" → 放弃。这正是产品最怕的结局 |
| ② **补救方案更贵** | 必须新增「首次启动引导」：检测系统语速 > 0.5 时弹窗，引导去系统设置调慢。这比 3 个 chip 复杂得多（要读系统设置、要写引导 UI、要判断"用户是否已处理"），**且跨应用副作用依然存在**（①的全局问题没解决） |
| ③ **留下技术债** | `AppSettings.speechRate` 字段**不能删**（备份 JSON 要向后兼容旧备份），只能弃用 → 代码里留一个"存了但不用"的字段，比保留功能更容易让人误解 |
| ④ **失去个性化空间** | 她学到第 30 课时可能希望"稍快一点"（0.4）。移除后，她要么去动全局设置，要么永远卡在慢速 |

### 1.3.4 建议的面板最终形态

> 把「语速」**从「显示设置」移到新的「朗读设置」区块**，与「朗读嗓音」同区。
> 这不是形式主义 —— 用户这次吐槽的本质是"**面板里混进了与系统重复的同类项**"。把它归入「朗读设置」后，语义上它明确是"**本 App 朗读**的参数"，而不是"系统显示参数"，重复观感自然消失。

```
显示设置
  字号          [小] [中] [大✓] [超大]
  按钮大小      [标准✓] [大] [特大]
  显示拼音                     [ 开 ]

朗读设置          ← 新区块
  语速          [很慢✓] [慢速] [稍快]     ← 切换后立即试听一句
  朗读嗓音      [自动（推荐）✓] [普通话] [中文（台湾腔）]   ← 去重后 ≥2 项才显示

进度备份与恢复
  [ 备份进度 ]  [ 恢复进度 ]
```

## 1.4 为什么这么设计（对母亲友好角度）

| 她的困难 | 设计怎么应对 |
|---|---|
| 看不懂技术名词 | 所有引擎机器名（`cmn-Hans-CN`、`Chinese (China)`）翻译成 `普通话` / `中文`；「系统推荐」简化为「推荐」 |
| 选项多 = 决策压力 | 去重后只剩 1 个 → **整行隐藏**，不给她做无意义的选择 |
| 怕点错、怕弄坏 | 「自动（推荐）」是默认且永远可达的安全值；点错嗓音随时可换回，零惩罚 |
| 不知道自己改了什么 | 切换语速 / 嗓音**立即试听一句**，听感=反馈 |
| 需要"慢"才能听清 | App 内 3 档语速默认「很慢」，开箱即用，不依赖她去动系统设置 |
| 听不懂"系统设置" | 0 嗓音时的引导文案由开发者黑话改写为「朗读声音由平板提供，可在『系统设置 → 文字转语音』里开启中文语音」 |

## 2.1 数据模型

### 2.1.1 章节默认生字 —— 算法

```
输入：chapter（StoryChapter）、learnedSet = ProgressService.learnedChars、kCharLibrary

1. tokens  = chapter.paragraphs.expand( p => parseRuby(p.ruby) )   // 复用 story_ruby.dart:37
2. hanzi   = tokens.where( t => !t.isPunctuation )                 // 复用 story_ruby.dart:22，剔除标点
3. freq    = LinkedHashMap<char, count>  —— 保序 + 计数（重复字自然去重，且留下频次权重）
4. cand    = freq.keys.where( c =>
                 !learnedSet.contains(c)          // ① 排除已学会
              && kCharLibrary.containsKey(c) )    // ② 只保留字库内有卡片的字
5. 排序：freq 降序（这章反复出现的字更值得先学）
        → tie-break：kCharLibrary[c].lessonId 升序（课序靠前的更基础）
6. take(N)，N = 8
```

**复杂度**：单章 `hanzi` ≈ 25–35，步骤 1–6 全程 **O(n)，n≈35**。即便 41 章全算一遍也不过 ~1500 次基本操作 —— **在 `build()` 里直接同步计算即可，不需要 `Future`、不需要缓存、不需要预计算表**。滚动流畅性由 `ListView.builder` 本身保证，生字条只是列表的最后 1 个 item。

**关于"是否排除极常用字"：✅ 建议不额外维护黑名单。**
理由：第 ① 步 `!learnedSet.contains(c)` 已经把"她早就学会的常用字（的、了、我、你）"自动排除了，这比一份静态黑名单**更个性化**（黑名单不知道她学没学会）。维护黑名单反而是额外负担且会误伤。

**关于"重复出现的字"**：用 `freq` Map 天然去重，并把频次用作**排序权重** —— 一章里出现 3 次的字，比只出现 1 次的更值得先学（这章绕不开它）。

**关于 N = 8**：
- 母亲畏难，一屏 20 个生字 = 压迫感；8 个 ≈ 3 课的量，"学完这一章就认识 8 个字"是**可完成的目标**。
- 超出 8 个的部分折叠为「还有 X 个」（点开全展示），不隐藏、不丢弃。

**⚠️ 第 ② 步的副作用（重要，需拍板）**：
故事里的专有字（悟、吒、蟒、嫦、娥…）**不在字库里** → 会被过滤掉，永远不出现在默认生字列表。
- 好处：点进去不会出现 `CharDetailScreen` 的"字库里没有这个字"错误页（负面体验）。
- 坏处：**故事生字的覆盖率会明显偏低**（四大名著/神话类尤其）。
- → 见待拍板 **W4**：是否要把故事高频字补进字库。

### 2.1.2 自标字 —— 存哪里

**✅ 建议：新增第 4 个 key `wq_marks_v1`，不塞进 `wq_progress_v1`。**

| 维度 | 塞进 `wq_progress_v1` | **新增 `wq_marks_v1`（建议）** |

| 备份兼容 | `BackupService` 需改（两种方案都要改） | 同样需改，但字段边界清晰 |

**数据结构**（与 `ProgressEntry` 同构，便于复用 `ReviewService` 的调度思路）：

```dart
// Store.kMarks = 'wq_marks_v1'
{
  "v": 1,
  "items": {
    "悟": { "b": "nezha|c1", "d": "2026-08-31", "s": 0, "g": 0 },
    //      b=首次标记位置(bookId|chapterId，用于回跳)  d=标记日期
    //      s=stage(0..4，与 ProgressEntry 同义)  g=1 表示「已学会」的降级标记
```

单条约 55 字节，**60 条 ≈ 3.3 KB**，SharedPreferences 毫无压力。

| 情况 | 处理 | 为什么（对母亲角度） |
|---|---|---|
| **整章无生字** | ✅ **显示鼓励语，绝不隐藏**：<br>`「这一章的字你都学过啦，真了不起！」` 赭石浅底小卡 + 一个 ✓ 图标 | 母亲畏难易放弃。**"没有生字"是她的成果、是她的正反馈**，必须被看见。隐藏 = 她以为功能坏了，或以为自己没学好 |

| **自标字不在字库里**（悟、吒、蟒…） | ✅ **允许标记**（她确实不认识），但点击后**不走 `CharDetailScreen`**（会显示"字库里没有这个字"= 错误页）。改为弹一个**轻量识字卡**：大号汉字 + 拼音（取自该字在故事里的注音）+ TTS 朗读 + 一行说明「这个字还没收进字库，先听一听」 | **保证"点任何圈出来的字都有正面反馈"**，绝不出现错误页 |
| **同一字重复点击** | 切换语义（圈 → 取消 → 圈），幂等，不重复计数 | 她手指抖可能连点，幂等能防止"点两下变两个"的混乱 |
| **标记了她其实已学会的字** | ✅ **允许，不纠正**（她的主观感受优先）。列表里归入"已学会"分组 | **纠正她 = 否定她的判断 = 挫败**。产品调性是"尊重母亲人格" |
| **圈字时翻章 / 退出未点「完成」** | ✅ 自动保存（每次点击即时落盘），不丢 | 绝不能让她"白圈了" |
| **备份 / 恢复** | 🔴 `BackupService` 必须带上 `wq_marks_v1` | 见 2.1.2 |

### 2.3.2 正文中「标记生字」的交互

#### 四方案对比

| 方案 | 操作 | 对母亲的问题 | 结论 |
|---|---|---|---|
| **A. 长按某字** | 手指按住 0.5 秒 | ❌ 老人手指抖，**按住 0.5s 最容易失败**（变成滑动或唤出系统菜单）；且"长按"是**隐形手势**，界面上没有任何提示告诉她可以长按 → **她永远发现不了** | ❌ |
| **B. 点字进入选中模式** | 点一下字 → 高亮 → 再点确认 | ⚠️ 与现有「点字朗读」（`ruby_text.dart:82-88`）**语义直接冲突**：她点字是想听读音，结果弹出标记框 → 困惑 + 怕点错 | ❌ |
| **C. 常驻「标记模式」开关** | 先开开关 → 再点字 | ⚠️ **两步行** + 需要**记住"我现在在标记模式"**（对老人是状态负担）；忘记关会一路误标 | ❌ |
| **D. ✅ 推荐：段落内「圈生字」按钮 + 点字即圈 + 再点取消** | 见下 | ✅ | ✅ |

#### 推荐方案 D —— 一句话说清操作

> **每个段落右下角、在现有「听这一段」旁边加一个大按钮「圈生字」；点它 → 这一段变底色 + 顶部出现醒目横幅「点不认识的字，就能圈出来」→ 点任意一个字，这个字立刻变蓝加粗、下方划线，并且马上念一遍给你听 → 再点同一个字就取消 → 点「完成」退出。**

**完整交互流程：**

1. **入口常驻**：每个段落卡片右下角，与现有「听这一段」（`story_reader_screen.dart:490-496`）**并排**新增一个大按钮「圈生字」（图标 `Icons.border_color_outlined` + 文字，热区 ≥72dp，与"听这一段"同规格同配色）。
2. **点「圈生字」→ 该段进入「圈字状态」**（**只影响这一段**，其它段落完全不受影响）：
   - 段落卡片背景变 `AppTheme.daiSoft`（浅黛青）+ 顶部插入醒目横幅：`点不认识的字，就能圈出来` + 右侧一个「完成」按钮
   - 段内**点任意汉字 → 立即圈出**：
     - 该字变 `AppTheme.dai`（黛青）+ 加粗 + 下方 2dp 实线下划线
     - **立刻 TTS 念一遍这个字**（`TtsService.speak(char)`）
     - 轻微放大回弹动画（120ms）
     - 即时落盘到 `wq_marks_v1`
   - **再点同一个字 → 取消圈选**（视觉复原 + 从存储移除）
3. **退出「圈字状态」有 3 种方式，任意一个都行**：点「完成」/ 点段落外任意处 / 翻章自动退出。

#### 为什么这个方案对老人友好（逐条对应她的困难）

| 她的困难 | 方案怎么应对 |
|---|---|
| **手指抖、按不准** | 全程**单击**，没有长按（长按要维持 0.5s，正是抖手最容易失败的动作）。圈字状态下把字的点击热区从现有的字号 1.15 倍宽（`ruby_text.dart:96`）**再放大到 1.4 倍** |
| **不理解长按 / 隐藏手势** | 「圈生字」是**看得见、写着字的大按钮**，不需要任何前置知识。就算她不认字，按钮上也有**一支笔在圈字**的图标 |
| **怕点错** | ① 圈错了**再点一下就取消**，零惩罚；② 圈字状态有**醒目横幅**告诉她"现在在做什么"，绝不会出现"我不知道点了个啥"；③ 退出方式多达 3 种，绝不困住她 |
| **需要即时反馈** | 点中一个字 → **立刻 TTS 念出这个字** + 视觉变蓝加粗 + 回弹动画。她**同时听到和看到**反馈，确信"我点中了" |
| **畏难、怕任务重** | 不做"必须标记完才能走"。随时「完成」随时走；一个都不标记也能正常读完 |
| **会念但不识字（关键矛盾）** | 她**能听出"这个字我不会念"**。点中后 TTS 念一遍，正好帮她**确认"对，就是这个字我不会"** —— **听觉反馈对她比对普通老人更有效**，这是本方案把"朗读"嵌入标记动作的核心原因 |

#### 标记后的视觉反馈

| 状态 | 视觉 |
|---|---|
| 圈字状态中（强） | 字色 `AppTheme.dai`（黛青）+ 加粗 + 下方 2dp **实线**下划线 |
| 阅读常态中（弱） | 字色保持 `AppTheme.ink`，仅下方 1.5dp **赭石**（`AppTheme.zhe`）下划线 |
| 已学会的标记字 | 淡黛青下划线 + 列表末尾 + 小 ✓ |

**为什么常态用赭石不用黛青**：黛青在本 App 里已是"主操作 / 已学会"的语义色（`hanzi_screen.dart:98-99`），再用会**与"已学会"混淆**。赭石是"次操作/分类"色，中性、不抢眼。
**绝不使用**：删除线、打叉、标红 —— 红色 = 错误 = 她会紧张。

#### 取消标记的两个途径

1. **在圈字状态里再点该字**（最直接，切换语义）
2. **在「我圈的字」列表里，每个字右上角一个小「×」热区（≥48dp）**，点一下即取消，并温和提示 `已经取消圈选`
   - **不弹二次确认框**：取消是可逆的（她还能重新圈回来），二次确认只是增加负担
   - 全程不用长按（列表里也一样）

## 2.4 复习闭环

### 冲突分析

| 项 | 简报所述 | **代码实际** | 差异 |

| 间隔 | 10分钟 / 1天 / 3天 / 7天 / 15天 | `intervals = [1, 3, 7, 30]`（`review_service.dart:10`） | ✅ 以代码 `[1,3,7,30]` 上限 20 为准（W6 已拍板） |
| 每日上限 | 15 个 | `buildQueue(limit: 20)`（`review_service.dart:26`） | ⚠️ **不符** |

**真正的冲突**：自标字 / 默认生字若直接写进 `ProgressService._entries`，会**挤占每日 20 个的复习额度**，把课程字挤出去 → 打乱"按课推进"的主线。更糟的是：母亲刚从《哪吒闹海》里圈了 10 个字（悟、吒、妖、蟒…），第二天复习页**全是这些生僻故事字** → 难度陡增 → 打击信心。

### 建议方案：**不改动 `ReviewService`，走"独立存储 + 轻量复习"**

| # | 规则 | 理由 |
|---|---|---|
| 1 | 自标字 / 默认生字**不写进 `ProgressService._entries`** | 因此**不参与 `dueToday` / `buildQueue`，不占用 20 个/天额度**，不干扰 1/3/7/30 主线 |
| 2 | 单独存 `wq_marks_v1`，每项带 `d`（标记日）+ `s`（stage，初始 0） | 与 `ProgressEntry` 同构，将来若想并入调度，改造成本极低 |
| 3 | **学习动作**：点任意生字 → `CharDetailScreen` → 点「标记为学会」→ **同时做两件事**：<br>· `progress.markLearned(char)`（进入正式进度 + 正式复习队列）<br>· `wq_marks_v1` 里把该字标 `g=1`（保留标记记录，视觉降级） | 既进了正式流程，又保留了她的"圈选史" |
| 4 | **轻量复习入口**：`HanziScreen`（我的）**新增第 3 个 Tab「我圈的字」**（现有 2 个 Tab：`hanzi_screen.dart:53-56`）<br>列出全部自标字，按 `stage` 升序 + `d` 升序（生疏优先），点进 `CharDetailScreen`<br>列表**默认只显示前 30 个**，其余折叠 | 为什么放「我的」而不是复习页：**复习页是"系统安排给我的任务"，而"我圈的字"是她自己的东西**，语义上属于收藏夹；且复习页已有 20 个/天的节奏，混进去会乱 |
| 5 | **不设每日上限** | 她主动点进去看是自发行为，不是被动任务，不该被限额 |

### 简化方案（备选，供拍板）

> **干脆不做自标字的间隔复习**，只做「圈出来 → 单独学 → 学会了留个勾」。
>
> **理由**：故事阅读本身就是**高频自然复现** —— 她会反复读喜欢的故事，同一个字会在不同故事里再遇到，这比算法调度更自然，也更符合产品"零挫败、小步慢走"的调性。
>
> 代价：没有算法保证她一定会再遇到。收益：实现量减半，且不给"我的"页新增 Tab。
> → 见待拍板 **W5**。

## 2.5 为什么这么设计（对母亲友好角度）

| 她的困难 | 设计怎么应对 |
|---|---|
| 畏难、容易放弃 | ① 章末生字**只显示 8 个**（可完成的目标）；② 整章无生字时**显示"你都学过啦，真了不起"**（把空白变成表扬）；③ 自标字上限 60（防止一屏几百个"我不会"压垮她） |
| 怕点错、怕弄坏 | 圈错**再点一下就取消**，零惩罚；3 种退出方式绝不困住；取消不弹二次确认 |
| 需要有成就感 | "我圈过 12 个字，学会 7 个"；学会的字**保留标记 + 打勾**，不是消失 |
| 手指抖 | 全程**单击无长按**；圈字状态热区放大到字号 1.4 倍；生字卡 ≥72dp |
| 不识字但需要确认"哪个字我不会" | 点中即**念一遍**，用她的听觉能力补足视觉识别的不足 |
| 怕被纠正、怕显得笨 | 她标记了其实已学会的字 → **不纠正、不提示**，归入"已学会"分组 |
| 怕功能"坏了" | 点任何圈出来的字都有正面反馈（字库外的走轻量识字卡，**绝不出现"字库里没有这个字"**） |
