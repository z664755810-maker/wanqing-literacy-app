## 三、语音设置去重

- **根因**：原设置页「朗读嗓音」列出「系统推荐」+ 三个 `zh` 选项，实际是**同一种嗓音**的无效重复（系统 TTS 多次上报同一嗓音，旧 `getZhVoices()` 零去重）。
- **修法**：`tts_service.dart` 新增 `_loadDedupedVoices()` 四步去重管道（宽过滤 zh/cmn → 规范化 key `nameKey|normLocale` → `name==locale` 标 `#generic` → 排序「普通话」优先），只列**真正有区分度**的嗓音 + 「自动(推荐)」；点芯片即应用并试听。
- 平板可直接调语速/音调，面板**不再重复**提供同类调节；原「语速 3 档（很慢/慢速/稍快）」从显示设置移到新「朗读设置」区并保留（用户拍板保留）。

## 附：关于「包体 526MB 算不算大」

用户问「企业级软件怎么处理内存过大」。结论：**这四层手段里，对本项目只有两层适用**。

| 手段 | 干什么 | 本项目 |
|---|---|---|
| 编码压缩 | PNG → WebP/AVIF，同画质降 60–80% | 适用，但用户已表态体积无所谓 |
| 分辨率分级 | 按屏幕密度出多套图，不给平板喂 4K 图 | 适用 |
| 按需下发 | App Bundle + 资源分包，装完只有壳，用到再联网下 | **不适用**——本项目硬性要求纯离线、无网也能读 |
| 内存管控 | LRU 缓存 + 按控件尺寸解码，只留当前页 | 适用（阅读器本就按段渲染，天然只加载当页） |

纯离线是这个 App 的核心约束，它直接把最有效的「按需下发」这条路堵死了——所有图必须随包带走。所以「体积无所谓」在这个场景里不是偷懒，而是**在离线约束下唯一自洽的选择**。真要控体积，只剩压缩和降分辨率两条路，而那两条要用画质换。
